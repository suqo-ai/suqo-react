# Changelog

All notable changes to this project are documented here. Entries from 0.0.2 on are generated by
semantic-release from conventional commits and land through the release PR; see RELEASING.md.

## [0.0.1](https://github.com/suqo-ai/suqo-react/releases/tag/v0.0.1)

The first published version, as `@suqo/react`.

### Features

- `<SUQOCheckout id="cks_…" />` — the embedded SUQO payment block as a React component, with
  `onReady`, `onSuccess`, `onFailure`, `onUnavailable` and `onLoadError`.
- `mode` prop (`'sandbox' | 'live'`, default `'sandbox'`) picks the SUQO origin without naming a
  URL. `origin` is optional and still overrides `mode` when set, for a staging mirror or a local
  mock server. `LIVE_ORIGIN`, `SANDBOX_ORIGIN`, `normaliseOrigin` and `CheckoutMode` are exported
  so a host app can resolve the same URL elsewhere.
- `onIntent` prop and `suqo:intent` message: the frame can ask this package to hand a bank/wallet
  deeplink (`intent://…`, `fonepayApp://…`) to your own code instead of attempting the navigation
  itself, which its sandbox never allowed. This package never navigates on it — only
  `javascript:`/`data:`/`file:`/`blob:` are refused, everything else passes through verbatim.
  Matches `js-checkout`'s `onIntent` and `suqo-react-native`, which drops this message as a no-op
  since its WebView already handles deeplinks through navigation interception.
- `DEFAULT_ORIGIN` (a deprecated alias for `SANDBOX_ORIGIN`), and the `ResultParams`,
  `ResultStatus`, `FailureStatus`, `UnavailableReason` and `LoadError` types.

### Requires

This is one half of a protocol. The SUQO web app must serve:

- `/c/<sessionId>` — the chrome-less payment block, posting `suqo:alive` from the route layout
  (not the block, or two deadlines collapse into one), reporting height from the card rather
  than the document, and posting `suqo:ready` on every settled state including errors.
- `/checkout/<sessionId>` — the hosted standalone equivalent, which is where the failure panel
  and `suqo:redirect` both send a buyer.

`PROTOCOL.md` in the `js-checkout` project is the contract.

### Notes

- `treeshake` is off in the tsup config on purpose: it routes the bundle through Rollup, which
  drops the `'use client'` banner, and Next.js App Router then refuses the package. `npm run
check:dist` asserts the directive survived.
- Unmounting while a buyer is mid-payment leaves their gateway window open. They finish and the
  webhook fires; only the callback is lost, because it belongs to a tree that no longer exists.
